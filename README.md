# SorcerStone оптимізація

Лаба на оптимізацію швидкодії. За основу взяв проект SorcerStone (рахує які слова найчастіше зустрічаються в harry.txt і виводить топ 30). Там було дві версії, на масивах (master) і на стрімах (гілка oop), їх переніс сюди як v1 і v2 без змін в логіці, щоб порівнювати на одних і тих самих даних.

Версії:

- v1 - оригінал на масивах
- v2 - оригінал з гілки oop на стрімах
- v3 - текст готується так само (regex + split), але слова рахуються через HashMap за один прохід
- v4 - оптимізована, без regex і без String: йде по байтах файлу один раз, слова рахує у своїй хеш таблиці, String створює тільки для тих слів що попали в топ, топ 30 вибирає купою а не сортує всі слова

Чому старі версії повільні: в обох для кожного унікального слова (їх ~5800) заново перебираються всі ~80000 слів тексту, тобто це сотні мільйонів порівнянь. В v1 ще й distinctString += в циклі і contains по рядку який весь час росте, а в компараторі для сортування на кожне порівняння викликається replaceAll.

Що знайшов по ходу:

- в v1 баг, contains шукає підрядок, тому слово "the" не попадає в список бо воно вже є всередині "another". Через це в топі v1 нема the, to, he, of, it, in і ще купи слів, тобто результат v1 просто неправильний
- в v2 час рахувався як between(now, start), аргументи переплутані і виходить від'ємне число
- v2, v3 і v4 дають однакові частоти по всіх 5764 словах, це перевіряється в Bench перед замірами

## Запуск

Потрібна Java 25.

```
javac -d out $(find src -name '*.java')
java -cp out chnu.edu.sorcerstone.Main v4
java -cp out chnu.edu.sorcerstone.Bench
./bench.sh
```

Main запускає одну версію (v1..v4) і виводить топ 30 і час як у викладача. Bench гоняє всі версії в одній JVM з прогрівом. bench.sh запускає кожну версію 5 разів в новій JVM (холодний старт).

## Результати

Мак на M-процесорі, JDK 25 (Corretto), під час замірів був ще запущений інший софт тому розкид великий, особливо у v1 і v2.

Холодний запуск, медіана з 5 запусків (як міряв викладач, один прогін в новій JVM):

| версія | час, мс |
|---|---|
| v1 arrays | 3058 |
| v2 streams | 3518 |
| v3 hashmap | 164 |
| v4 fast | 35 |

Після прогріву JIT (Bench), медіана:

| версія | час, мс | runs |
|---|---|---|
| v1 arrays | 2834 | 5 |
| v2 streams | 3809 | 5 |
| v3 hashmap | 31 | 158 |
| v4 fast | 2.7 | 1024 |

Висновок короткий: v4 швидша за оригінали десь в 90-100 разів на холодну і в 1000+ разів після прогріву. Основний виграш дає сама заміна вкладених циклів на хеш таблицю (v3), а відмова від regex і створення String дає ще приблизно в 5-10 разів.
